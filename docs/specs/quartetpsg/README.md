# Quartet PSG: unknowns, caveats, implementation notes

Files: SPEC.md (format, patches, conversions, timing), LOGS.md (the logs and what they show),
logs/ (32 reference write logs, the synthetic modules and the driver sources they were built
from).

## Feasibility (verified)

An earlier note called this format infeasible because the module is original Atari 68000 code.
That is not a blocker. The Eagleplayer itself only *hosts* that code, in the pattern the repo
already uses (Riff Raff, Benn Daglish SID, Mark II): it patches a few code words, runs the driver
on the 68000 and takes the YM register bytes from a site. It needs no YM2149 or other Atari
hardware emulation. Its conversion to Paula is simple and fully specified (SPEC 5, 6). With
synthetic driver modules of the shape the player expects, the reference plays both modes, all
subsongs and the song end, and a model from the spec matches it exactly (LOGS.md).

## Real modules

None found. The module index has no `sqt.` or `.sqt` files: the only matches are a Matt Furniss
`sqtitle` MOD and ProTracker MODs. A header search of the whole index for the detection rule
(four 0x6000 entries followed by 0x49FA at offset 16) finds nothing: 64 files start with four
branch entries, all other formats. No Rob Povey or Steve Wetherill directory exists apart from
Quartet ST material. The existing Quartet and Quartet ST specs had no real files either. Real
Quartet PSG music would come from Atari ST game rips (SNDH-style archives are not in the corpus).
Such files would have to be cut to the shape of SPEC 1 (the player expects the bare driver image,
as the Wanted Team adaptation ships it). That is why everything was checked on synthetic modules:
the patching, the sites, the timing and both conversions are fully covered, but what a real
driver does between them (its music logic, extra hardware accesses, registers it expects at
entry, more than one song-end site, envelope use) is untested (SPEC 10).

## Player data (not embedded: generated)

- `data/noise_1k.bin` (1024 bytes, mode 0) and `data/noise_16k.bin` (16384 bytes, mode 1): the
  player's noise buffers. They are not stored in the player but generated by the rule of SPEC 8
  (checked byte for byte against what the player generates), so a port can generate them
  instead of embedding the files.
- The 2-byte pulse waveforms (0xB2 0x4D; 0x70 0x90), the two volume tables, the period formulas
  and the noise period rules are small constants given in SPEC 5 and 6.

## Unknowns and caveats

- **Start-up constants.** SPEC 3.1's C_pre (1345 cycles in mode 1, 1269 in mode 0) was measured,
  not derived. It covers the check, the configuration read (which costs differently when the
  file exists), the two volume calls and host-call stubs. My own sum for mode 1 came to 4 cycles
  less. The mode-0 value assumes the reference's setup with no configuration file in either
  place. A different host order of calls shifts I and with it every mode-0 raster position.
- **Noise generation happens only once.** It runs on the player's first initialisation. A second
  module played without reloading the player starts about 1.84 million cc earlier than the
  first (SPEC 3.1). The logs all come from a fresh load.
- **Buffer addresses.** The LC values in the logs are the reference's (block at 0xADAC60, with
  only this Eagleplayer loaded). They change with the host's heap; a port uses its own.
- **Paula dependency.** Mode 0's waits poll the host Paula's audio interrupt flags (after a stop,
  up to one sample of the old period). A port must poll the same Paula at the same clocks. A
  Paula with a different stop or start rule changes every later write time. Mode 1 has no waits.
  Its start-up writes AUDxDAT = 0 on all four voices, which puts the host Paula's voices into
  manual mode before DMA is enabled. That affects the sound, not the write log.
- **Late ticks.** A mode-0 tick can exceed 70 940 cc (long stop waits). The next tick then
  starts as soon as it ends, and due times stay on the 70 940 grid (SPEC 3.5). This is host
  behaviour that the reference shows.
- **Volume and voice switches.** SPEC 7 comes from the player's logic. The reference host never
  changes volume or balance (factor 64) and never switches voices off, so this was not run.
- **Mode 1** needs the configuration file (SPEC 3.2). The logs `*_m1` were made with it in the
  host's `Env:` directory. UADE's default and the expected default for a port is mode 0.
- **Envelope registers** R11..R13 are never captured; YM envelopes are lost in both modes (player
  behaviour, not a port choice).
- **Degenerate modules** (no 0x00000056 marker after the patched range, marker at or after the
  computed end, subsong count 0, two adjacent song-end sites, a second site overwriting module
  offset 16) behave as described in SPEC 1.3 and 2.2. Of these, only "two adjacent sites" was
  run (`h3`). A port should reject the hanging cases.

## Errata found by the implementation

- SPEC 5.3 says no wait when the mask is 0; the reference does one interrupt-request poll
  (12 cycles, read, 17 cycles) even then, in both the stop wait and the start wait.
- The SPEC 3.1 walk costs that match every reference start time: a normal position 104 cycles
  (site test 29, first hardware test 29, second 29, step 17); a site position 101 (29 + 72) with no
  step, and the position after it skips the site test and costs 75; a hardware test found at the
  first form costs 58, at the second form 87.
- SPEC 5.4: the trailing 42 cycles for count 0 are undefined; charging nothing matches the logs.
- Mode 1 is selected by a config file; the port reads the file named by `QUARTETPSG_CFG`, else
  `~/.config/amigaplayer-rs/EP-Quartet_PSG.cfg` (the port's choice).
- No real module exists; all validation is on synthetic modules of the patched shape.
