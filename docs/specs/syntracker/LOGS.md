# Logs and reproduction

All files under the spec folder.

IMPORTANT: no real SynTracker module exists in the module archive (checked: public.module_index
name patterns `st.*`/`synmod.*` give only SidMon files named "St. Thomas - *.sd2"; the header
index headers/headers.sqlite has no file starting with `SYNTRACKER-SONG:`). Therefore ALL modules
here are synthetic, generated by tools/gen*.py from the format as read from the player. They
exercise every code path found, but not the habits of real composers.

## Modules (mods/*.synmod)

Main set (the 7 the spec is built on):

| module | what it covers |
|---|---|
| m1_synth | 3 synth instruments (sine/saw/square), envelopes, vibrato table pages, effects V, L, G, transposition, 2 positions (song end) |
| m2_scanmorph | wavetable scan with window page, turn positions with reflect and jump, morph filter phases, effect M, wave switch 0x41/0x42, effect A |
| m3_sample | 8-bit sample instruments: loop, no loop, zero length; L, G, V on samples; mixing sample and synth |
| m4_effects | A, O, U, D, E (glide), S (speed), F (CIA LED), B (jumps), instrument byte 0xFF, transposition, 3 positions |
| m8_eglide | 4 channels of E glides, downward glides in several channels per tick (the leftover-register quirk, SPEC 8.1) |
| m9_edge | instrument bytes 0x21..0x3F / 0x40 / 0xFF, wave switch during scanning, E, V with parameter 0xFF, B00 |
| m6_rand1 | random patterns/instruments/effects (seed 11), 4 positions |

Further: m5_jump (B jumps and B00 at the end, never ends), m7_rand2 (seed 29), r101 r202 r303 r404
r505 r606 (random, seeds 101..606), t_ch0..t_ch3, t_a..t_d (minimal modules that showed the
destination quirk SPEC 6.7: one or two channels start a note at row 0).

The random modules were produced by tools/gen.py (`rnd(seed)`), gen12.py, row 0 of every pattern
always starts an instrument (starting instrument 0 before any instrument is undefined).

## Reference logs (logs/)

| file | content |
|---|---|
| NAME.ref.log | DELI_WRITE_LOG of the 68k reference: lines `ADDRESS VALUE COLOUR-CLOCK`; first line `# module ADDR SIZE` (address of the module in memory). A long write to AUDxLC appears as two word writes at the same clock. Ticks are separated by gaps > 30000 cc. Writes before the first tick are the start sequence (SPEC 9). Also CIA (bfe001) writes. |
| NAME.dma.log | DELI_DMA_LOG: `CLOCK CHANNEL ADDRESS WORD` for every audio DMA word fetched. Used to check the waveform memory contents (SPEC 6.7). |
| NAME.gaps.tsv | per-write gap tables (tick, index, address, value, cc from first write of the tick, cc from previous write) for m1 m2 m3 m4 m8 m9 m6 r606 (tools/gaps_tsv.py) |

## Reproduce a reference log (68k player, silent)

    E=an empty directory
    SDL_AUDIO_DRIVER=dummy RUST_LOG=error DELIPLAYERS=$E DELIGENIES=$E DELI_NATIVE=0 \
    EAGLEPLAYERS=$HOME/.local/opt/uade/share/uade/players DELI_WRITE_LOG=/path/m1.ref.log \
    DELI_DMA_LOG=/path/m1.dma.log \
    the reference host binary \
        --player SynTracker --wav /dev/null --seconds 12 mods/m1_synth.synmod

(tools/ref.sh NAME SECONDS does this for mods/NAME.synmod into logs/.) The Eagleplayer 2.06
"SynTracker" and the UADE one have identical player code (only the 8-byte tag at the start of the
file differs: DELIRIUM vs EPPLAYER); the logs are from the UADE copy. Logs end at the song end
(positions wrap) or at the --seconds limit (m4, m5, m9: B jumps loop forever; 2000 ticks / 40 s).

Compare a port's log tick by tick with the reference: tools/replay-cmp.py REF.log PORT.log of the
repo (the model that produced SPEC.md used this grouping: split at gaps > 30000 cc, compare
(address, value) sequences).

## What the logs confirm

A model written from SPEC.md sections 4-9 (not shipped; it exists only in the author's private
notes) reproduces, for all 17 mods: every write's address and value and the order, for every tick:
 ~9200 ticks and >100 000 writes; 0 differences. The audio DMA words were compared against the
 model's playing waveform memory: all words equal except those fetched during the end-of-tick
 128-byte copy (about 0.2 %: the fetch sees half-copied memory; timing of the copy in 10.2).

Features first found wrong in the author's own model and fixed by these logs (so they are
covered by the logs): the default arpeggio rate of 1 (steps every tick); the scan destination
pointer advancing by 32 per writing channel (t_a..t_d); the leftover upper half of the glide
divide (m8_eglide); the vibrato "period below the lowest note" read (r606 ch1 tick 264); zero
length sample load address = start of the zero area (m3_sample).

## Timing logs

Gap tables of SPEC 10 were fitted to the *.gaps.tsv / .ref.log data of all 17 modules. Check
(author's script, ~29000 plain ticks): PER gaps within 1 cc in 100 %, VOL gaps within 2 cc in
99.5 %, DMACON-gap model within 10 cc in 75 %, within 20 cc in 96 %.
Also measured: tick-to-tick distance 69700..72200 cc, typical 70940 (host); first write of a plain
tick to its last (DMACON): about 1800..2000 cc for four idle channels (PER0 -> DMACON 1823 in
m1 tick 0).
